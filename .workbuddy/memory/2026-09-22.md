## T6 layout 模块完成（手写 LinearLayout 测量）

- 新增 `crates/velm/src/layout/{mod,measure}.rs` + `crates/velm/tests/layout.rs`；`lib.rs` 无条件 `pub mod layout`。
- 16 个 host 单测全绿（累计 37）；三目标 clippy `-D warnings` + fmt 全绿。
- 修正 docs 两个缺陷：容器 WrapContent = 子节点「主轴求和 / 交叉轴取最大」（非 MatchParent）；margin 四向既偏移位置也扣减可用尺寸。

### 算法要点（T7/T11/T13 会依赖）

- 两遍 O(n)：`measure` 求宽高写 `computed_rect`（x/y 置 0）→ `place` 写绝对坐标。容器 WrapContent 依赖子节点尺寸，故求尺寸必须先于定位；两遍各遍历一次全树。
- 关键坐标约定：`place` 的 `content_x/content_y` 是**父节点内容区原点**，子节点 rect = 父原点 + 主轴游标 + 自身 margin。v1 无 padding。
- 文本度量隔离为 `pub fn estimate_text_width(text, text_size_px)`（chars * size * 0.6），P1 换 skrifa advance 时只改这一处。
- 根节点可用区 = 整窗尺寸 - 根自身 margin（否则 MatchParent 根带 margin 会溢出）。
- v1 限制：WrapContent 容器内的 MatchParent 子节点按上界一次求值，不实现 Android 二次 measure。

### 语义决策（SPEC §7.5 已回写）

- 容器「回落」发生在子节点 `find_map` 之内：子节点及后代都不产生消息时继续探测更下层兄弟 → **未绑监听的容器对点击透明**，绑了监听的容器才拦下点击。两条回归用例钉住穿透/拦截。

### 教训（通用，值得复用）

- **density 类 bug 只在 density≠1 显现**：T7 的端到端用例（layout + hit_test 串联）暴露 T6 缺陷——margin 未乘 density，三处消费点（位置偏移 / 可用区扣减 / 主轴推进量）把 dp 当像素用。T6 单测全用 density=1，故完全没暴露。已统一收敛为 `margin_px(margin, density)`，并补两条 density=2 回归。
- **结论**：凡是 dp↔px 混用的模块，回归用例必须包含 density≠1 分支；跨模块端到端用例（layout→hit_test）比单模块用例更容易抓到这类单位错误。
